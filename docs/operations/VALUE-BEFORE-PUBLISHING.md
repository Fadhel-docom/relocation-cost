# قانون «القيمة قبل النشر» — إلزامي

**ينطبق على كل صفحة وأداة وميزة ومقال وتغيير SEO في هذا المشروع.** هذه بوابة قبول إلزامية وليست نصيحة اختيارية.

## القانون
لا ننشر العمل إلا عندما يقدّم إجابة أو فائدة واضحة لحاجة حقيقية لدى الزائر، وبعد التحقق من الدقة والأصالة وسهولة الاستخدام وقابلية الاكتشاف. صحة البرمجة والاستعداد للفهرسة ضروريان، لكنهما وحدهما لا يصنعان قيمة بحثية.

## المطلوب قبل التطوير
1. **تحديد نية حقيقية:** اكتب السؤال أو المشكلة المحددة التي يريد الزائر حلها. استخدم أدلة موثوقة متاحة مثل نتائج البحث وبيانات Search Console/Bing وصفحات المنافسين والمصادر الرسمية. ميّز الافتراض عن الحقيقة، ولا تخترع حجم بحث أو طلبًا.
2. **فحص البدائل:** راجع المنافسين أو البدائل ذات الصلة، وسجّل الروابط وتاريخ الفحص ونقاط القوة والنواقص والدليل. لا تدّعِ مراجعة شاملة لم تُنجز.
3. **تعريف القيمة المضافة:** اكتب جملة توضّح ما الذي سيتمكن الزائر من فعله أو فهمه أو تقريره أو توفيره، ولماذا يستحق الحل الاختيار بدل البدائل.
4. **اختيار الشكل المناسب:** أنشئ الشكل الذي يحل المشكلة بأفضل طريقة: حاسبة أو دليل عملي أو مقارنة أو قائمة تحقق أو رسم توضيحي أو غير ذلك. لا تفرض المقال على كل فكرة.
5. **تحديد الأدلة والحدود:** استخدم مصادر أولية أو موثوقة عند الحاجة، واشرح الافتراضات وطريقة الحساب وعدم اليقين والقيود وملاحظات السلامة. لا تختلق أسعارًا أو أرقامًا أو اختبارات أو تجربة شخصية.

## بوابة إلزامية قبل النشر
- [ ] الجمهور المستهدف والمشكلة أو السؤال واضحان.
- [ ] توجد فائدة عملية مميزة؛ ليس المحتوى حشوًا أو إعادة صياغة سطحية أو صفحة شبه مكررة لأجل SEO فقط.
- [ ] تمت مراجعة البدائل ذات الصلة وتحديد الفرق عنها بناءً على أدلة.
- [ ] تم التحقق من الحقائق والحسابات والأمثلة والمصادر، مع توضيح عدم اليقين والقيود.
- [ ] تعمل الصفحة أو الأداة على الهاتف، وتراعي الوصولية المناسبة، وتتعامل مع حالات الخطأ والمدخلات الطرفية عند انطباق ذلك.
- [ ] العنوان والعناوين الداخلية والبيانات الوصفية وcanonical وقابلية الفهرسة والبيانات المنظمة وsitemap والروابط الداخلية صحيحة حيث يلزم، بلا حشو كلمات مفتاحية.
- [ ] نُفذت الاختبارات وفحوص الجودة فعلًا؛ ويُذكر ما لم يُختبر بوضوح ولا يُعرض على أنه ناجح.
- [ ] توجد خطة متابعة مناسبة، مثل الظهور والنقرات أو إكمال استخدام الأداة أو الأخطاء أو مؤشر آخر ملائم.

## بعد النشر
عندما تتوفر بيانات كافية، راجع الأداء الحقيقي وحسّن الصفحات ذات الظهور والنقرات الضعيفة، أو النية غير المناسبة، أو الاستخدام المربك، أو الحقائق القديمة، أو الروابط المعطوبة. لا تعالج الأداء الضعيف بإنتاج جماعي لصفحات متشابهة قبل تشخيص السبب.

## قاعدة القرار
إذا تعذّر شرح فائدة الزائر أو الأدلة أو الفرق الحقيقي عن البدائل، **فلا تنشر بعد**؛ حسّن الفكرة أو ابحث أكثر أو اتركها. النشر والفهرسة ليسا دليل نجاح بحد ذاتهما؛ القيمة الفعلية والنتائج المتحقق منها هي المعيار.

## شرط كل Pull Request
كل PR يغيّر المحتوى الظاهر للزائر أو الوظائف أو SEO يجب أن يذكر:
- حاجة الزائر والدليل عليها
- القيمة الجديدة للزائر
- الفرق عن البدائل
- ما تم التحقق منه وما بقي دون اختبار
- كيف سنقيس النتيجة أو نراجعها لاحقًا

يمكن لتغييرات التوثيق فقط أن تذكر أن اختبارات التطبيق لم تُشغّل والسبب. لا تضمن الزيارات أو الأرباح.
